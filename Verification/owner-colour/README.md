# 男主人材质修复

本轮只改本地工程，未推送 GitHub、未更新 Mac 或完整工程包。

原因：贴图和材质资产存在，但男主人骨骼网格的八个材质槽未保存，重新加载后全部为空。原导入脚本修改 Unreal 结构体数组时未逐项写回，也没有确保模型包标记修改并强制保存；材质绑定还早于最后一次 FBX 动画导入。

修复：导入结束后按槽名绑定身体、皮肤、帽子、裤子、鞋、上衣、牙齿和眼睛八套原始材质。逐项写回数组，标记模型修改，并强制保存。材质启用骨骼网格用法，颜色贴图保持 sRGB。保留原始贴图、UV、动画、模型尺寸和场景灯光。

- `before-materials.json`：新进程回读，八槽为空。
- `after-materials.json`：修复后另起编辑器进程回读，八槽、贴图路径、色彩空间和骨骼材质设置通过。
- `Tools/import_resident_avatar.py`：以后重新导入也会在最后正确绑定和保存。
- `Tools/repair_resident_materials.py`：修复已有模型，不触碰动画或重新导入 FBX。
- `Tools/verify_resident_materials.py`：从磁盘重新加载并核验每个槽位。
- 现有 `ResidentBoneMotion` 检查新增本地男主人的八槽绑定及部位匹配校验。

实机截图 `owner-fixed.png` 已确认帽子、肤色、原始深蓝上衣、卡其裤与白鞋恢复；没有改变场景光源或用自发光掩盖缺失材质。`fps.json` 为颜色检查专用近距离机位：1920×1080、100% 渲染比例、高质量软件 Lumen，平均 77.12 FPS、最低五秒平均 70.30 FPS，P99 17.16 ms；不与此前其他机位的帧率作直接比较。此处主人暂时停在疑惑姿态，便于检查材质；普通游戏巡逻逻辑未改。

针对 `BadCatLab.World.ResidentBoneMotion` 的回归检查通过（1 项，0 失败、0 警告），包括新加的八槽材质非空与部位匹配检查，以及原有走路/待机骨骼运动检查。报告位于 `tests/index.json`。另一个任务同时在修改猫的动作，本轮保留这些改动；不将其他任务的改动归入本次颜色修复。
